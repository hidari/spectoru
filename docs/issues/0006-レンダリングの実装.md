# [Phase 7] レンダリングの実装

親: [0001](./0001-v0.1リリースまでのロードマップ.md)
依存: [0005](./0005-application層の実装.md)

## 目的

`TemplateEngine` ポートに実装を与え、IR 群から単一 HTML の仕様サイトを生成する。

## 方針: 外部依存ゼロ

CDN を含め外部ホストへのリクエストを一切行わない自己完結 HTML とする
（判断の経緯は [0002](./0002-中間表現のproject層導入とport拡充.md) を参照）。
CSS / JS / 検索インデックスをすべてインライン化する。

## セキュリティ

**テスト名は任意の文字列であり、`<script>` や `"` を含みうる。**
HTML 埋め込み時のエスケープは必須で、これを契約テストで固定する。

- HTML テキストコンテキスト: `& < > " '` をエスケープ
- JS 埋め込み（検索インデックス）: JSON としてエンコードした上で `</script>` の
  文字列が閉じタグとして解釈されないよう `<` をエスケープする
- 属性値コンテキスト: 引用符とエスケープを一貫させる

これは「ユーザーの内部仕様を並べたサイト」であり、テスト名の出所は自分たちの
リポジトリだが、外部コントリビュータのテスト名がそのまま埋め込まれる経路がある
以上、信頼できない入力として扱う。

## サイト構造

- サイドバー: プロジェクト → ソース → ファイル → グループの階層ツリー
- メインエリア: 選択されたグループのサブグループと spec をネスト表示
- 検索バー: テスト名のインクリメンタルサーチ
- 統計ヘッダー: spec 数、言語別内訳、警告数

複数フラグメントを渡した場合、サイドバー最上位にプロジェクト名が並ぶ。

## 決定: 検索インデックスを別に持たない

検索用データを JSON として別途埋め込むと、テスト名が HTML とデータの二重に載る。
ページサイズが倍になるうえ、エスケープが必要な経路も 2 つに増える（HTML テキストと、
`</script>` で閉じられうる script 要素の中身）。

代わりに仕様ツリーを完全な HTML として描き、絞り込みは JS が DOM のテキストを
見て行う。データの出どころが 1 つになり、JS を無効にしても全仕様が読める。

- 正規化（全角英数の半角化 + 小文字化）はページ側の 1 箇所だけで行う。
  Rust 側にも同じ規則を書くと索引とクエリで食い違いうる
- 部分一致（`indexOf`）。日本語では空白分割によるトークン化が機能しない
- 検索対象は spec 要素のテキスト全体（テスト名・言語・ファイルパス・行番号）
- 一致した spec を持たないグループ / ソース / プロジェクトと、対応する
  サイドバー項目を隠す

## 決定: レイアウトは選択状態を持たない

本文には全プロジェクトのツリーを常に描き、サイドバーはアンカーリンクにする。
「選択中のグループ」という状態を持たないので JS 無効でも成立し、実装も単純になる。

## テスト

- **エスケープ**: `<script>` や引用符を名前・グループ名・プロジェクト名・
  ソース名・診断メッセージ・ファイルパスに含む spec が、実行可能なタグとして
  現れない
- **危険なスキーム**: `javascript:` の `repository` が `href` にならない
- 出力に外部リソース読み込み（`<script src` / `<link` / `<img` / `@import`）と
  外部通信 API（`fetch` / `XMLHttpRequest` / `WebSocket`）が含まれない
- 単一プロジェクト / 複数プロジェクト集約
- 空の IR でも壊れた HTML にならない
- 同じ IR から常に同じ HTML が出る

### 実ブラウザでの確認（実施済み）

契約テストは文字列の検査でしかないため、Chromium（headless）で実際に読み込んで
確認した。spectoru 自身のソースから生成した 206 spec のサイトで:

- 外部リクエスト 0 件、JS エラー 0 件
- 検索が spec・グループ・サイドバーを正しく絞り込む
- 一致 0 件のとき「一致する仕様がありません」を表示する

XSS については 7 種のベクタ（`<script>` 各所、`<img onerror>`、属性抜け出し、
`javascript:` href）を仕込んだ IR を描画し、`window.__pwned` が未定義のまま、
`img` 要素 0 個、外部 href 0 件、ダイアログ 0 件であることを確認した。

この確認は手動で行ったため、自動化は 0007 の E2E に含める。
