# [Phase 8] CLI 配線と E2E テスト

親: [0001](./0001-v0.1リリースまでのロードマップ.md)
依存: [0006](./0006-レンダリングの実装.md)

## 目的

`fn main() {}` のままになっているエントリポイントを実配線し、
CLI として使える状態にする。

## 実装対象

- `CliParser` の clap 実装。`CliCommand` への変換のみを担い、clap の型を
  application 層に漏らさない
- `cli::run` で adapter を組み立てて app 層に注入する
- `main.rs` は `run` を呼び `ExitCode` に変換するだけにする

## サブコマンド

```
spectoru build   --config <path> --out <dir>   [--strict] [--revision <sha>]
spectoru extract --config <path> --out <file>  [--strict] [--revision <sha>]
spectoru render  --fragments <files...> --out <dir>
spectoru lint    --config <path>               [--strict]
```

`--revision` は CI で git メタデータが取れない環境（shallow clone、
コンテナ内など）向けの明示指定。指定があれば `GitProvider` より優先する。

## 終了コード

| 状況 | code |
|---|---|
| 正常終了 | 0 |
| 警告あり + `--strict` | 1 |
| 実行エラー（設定が読めない、出力できない等） | 2 |

警告と実行エラーを別コードにすることで、CI 側で「仕様の書き方の問題」と
「ツールが動かなかった」を区別できる。

## エラー出力

`SpectoruError` を人間が読めるメッセージとして stderr に出す。診断は
ファイルパスと行番号を含む形式で出力し、エディタから辿れるようにする。

## テスト

- CLI パースの単体テスト: 各サブコマンド、必須引数の欠落、未知のフラグ、
  `--fragments` の複数指定
- E2E: 実バイナリを一時ディレクトリ上の fixture プロジェクトに対して実行し、
  生成物と終了コードを検証する
  - `build` が HTML を生成する
  - `extract` が JSON フラグメントを生成し、それを `render` に渡せる
    （extract → render のラウンドトリップ）
  - `lint --strict` が警告ありで 1 を返す
  - 存在しない設定ファイルで 2 を返す
- ブラウザ E2E（0006 から持ち越し）: 生成 HTML を headless Chromium で読み込み、
  外部リクエストが 0 件であること・検索が絞り込むこと・XSS ベクタが無効化
  されていることを自動で検証する。0006 では手動確認にとどめた

## 決定: `--help` / `--version` は失敗ではない

「使い方を知りたい」も利用者の意図の 1 つなので、`CliCommand::Print { text }` として
コマンドの一種で表す。エラーとして扱うと終了コード 2 になってしまう。文面は
CLI ライブラリが組み立てたものをそのまま運び、表示と終了コードの決定は合成側が行う。

## 決定: 合成ルートは `src/cli.rs` に置く

具象 adapter を名指しするのはこの層だけ。`app/` は trait しか知らないため、
ここを差し替えれば別の実装構成でも同じユースケースが動く。`main.rs` は引数を
集めて渡すだけにとどめ、判断を持たない（CLI の振る舞いを `cli::run` 側で
テストできるようにするため）。

## 実バイナリの手動確認で見つけた不具合

`spectoru build`（設定が作業ディレクトリ直下）だと、設定ファイルの親ディレクトリが
空パスになる。空パスはディレクトリとして開けないため git の参照が必ず失敗し、
リポジトリ内で実行しているのに `git_revision_unavailable` の警告が出ていた。
最も普通の使い方で常に踏む経路だったが、Fake はパスを見ていなかったため
層別テストをすり抜けていた。カレントに読み替えて修正し、git に渡すディレクトリを
記録する Fake で回帰テストを追加した。

## 併せて対応

- `cargo xtask e2e` を追加。E2E は `cargo xtask test` にも含まれるため CI で
  別途走らせる必要はなく、CLI を触っているときの反復を短くするための入り口
- `DiagnosticCode` / `DiagnosticLevel` / `Language` の機械可読な文字列表現を
  core のメソッドに集約した。HTML と CLI で同じ表を二重に持っていた

## 持ち越し

ブラウザ E2E（0006 からの持ち越し）は見送った。node と Playwright を CI に
持ち込む必要があり、テスト 1 つのために依存とワークフローが増える。代わりに
CLI の E2E に、パイプライン全体を通したエスケープの回帰テストと、外部リソース
読み込みが無いことの検査を入れた。ブラウザでの確認は 0006 で手動実施済み。
